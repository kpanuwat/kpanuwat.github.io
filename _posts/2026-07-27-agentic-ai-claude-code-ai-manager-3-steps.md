## TL;DR

**Agentic AI** เปลี่ยน AI จาก "ระบบตอบคำถาม" เป็น "ระบบที่ตัดสินใจและลงมือทำเองจนกว่าจะถึงเป้าหมาย" — Claude Code คือตัวอย่างของเครื่องมือแบบนี้ ทักษะที่คนต้องมีตอนนี้ไม่ใช่การเขียนโค้ด แต่คือการเป็น **AI Manager**: มอบหมายงาน ตรวจสอบผลลัพธ์ และเชื่อมต่อเครื่องมือ ผ่าน 3 ขั้นตอน — สื่อสารด้วยภาษาธรรมชาติ, ทดลองกับงานจริง, และเชื่อมต่อเครื่องมือผ่าน MCP

## Background / Why this matters

AI แบบเดิม (chatbot ตอบคำถาม) ต้องการให้คนบอกทีละขั้นตอน ถ้าขั้นตอนไหนพลาด คนต้องกลับไปแก้เอง งานแบบนี้ยังต้องมีคนคอยกำกับตลอดเวลา ไม่ต่างจาก automation สคริปต์ทั่วไปที่ "ทำตามที่สั่งเป๊ะๆ" เท่านั้น

**Agentic AI** ต่างออกไปตรงที่ระบบสามารถ *"take action on its own towards a goal"* — คนบอกแค่ผลลัพธ์ที่ต้องการ ระบบจะไปคิดเองว่าต้องทำขั้นตอนอะไรบ้างแล้วลงมือทำจนเสร็จ [1] นี่คือเหตุผลที่ทักษะสำคัญของคนทำงานตอนนี้ไม่ใช่การเขียนโค้ดเก่งขึ้น แต่คือการรู้จัก "บริหารจัดการ AI" ให้ทำงานแทนได้อย่างถูกต้องและปลอดภัย — เหมือนการบริหารพนักงานใหม่ที่ฉลาดแต่ยังไม่รู้จักบริบทงานของเรา

ความเสี่ยงที่แท้จริงไม่ใช่ "AI จะแย่งงาน" แต่คือ "คนที่ใช้ AI เป็น จะทำงานแทนคนสองคนได้" — องค์กรที่ปรับตัวไม่ทันจะเสียเปรียบคู่แข่งที่ใช้ AI คล่องกว่า [1]

## Deep Dive

### Agentic AI คืออะไร ต่างจาก automation เดิมยังไง

Automation แบบเก่าทำงานแบบ deterministic: กำหนด rule ไว้ล่วงหน้า ถ้า input ไม่ตรงกับ rule ระบบจะพังหรือหยุดทำงาน ต้องรอคนแก้ Agentic AI ใช้โมเดลภาษาเป็นตัวตัดสินใจแบบ dynamic — รับเป้าหมาย, ประเมินสถานการณ์, เลือก action, ตรวจผลลัพธ์ (verify), แล้ววนซ้ำจนกว่าจะบรรลุเป้าหมาย loop นี้เรียกว่า **agentic loop** [1][2]

### Claude Code: ตัวอย่างของ Agentic AI ที่จับต้องได้

Claude Code ต่างจาก AI แบบแชททั่วไปตรงที่มันใช้ **repository (โฟลเดอร์โปรเจกต์)** เป็นความจำถาวร — อ่านไฟล์ทั้งหมด เข้าใจบริบทของงาน แล้วทำงานที่ซับซ้อนหลายขั้นตอนได้เองแบบต่อเนื่อง ไม่ใช่แค่ตอบคำถามทีละครั้ง [2]

งานวิจัยจาก Anthropic เกี่ยวกับการใช้งานจริงพบรูปแบบ **division of labor** ที่ชัดเจน: คนเป็นผู้ตัดสินใจ **"จะสร้างอะไร" (what to build)** ส่วน agent เป็นผู้ลงมือหาวิธีและทำ **"จะสร้างอย่างไร" (how to build it)** [3] นอกจากนี้ยังมีรูปแบบ **parallel processing** — Claude Code สร้าง sub-agent หลายตัวเพื่อประมวลผลงานหลายอย่างพร้อมกัน (เช่น วิเคราะห์ไฟล์ข้อมูลหลายไฟล์พร้อมกัน) ลดเวลาทำงานรวมได้มาก [2][3]

### 3 ขั้นตอนสู่การเป็น AI Manager

**ขั้นตอนที่ 1 — Natural language communication (สื่อสารด้วยภาษาธรรมชาติ)**

เริ่มจากปฏิบัติกับ AI เหมือนพนักงานใหม่ที่ฉลาดแต่ยังไม่รู้จักงานของเรา: อธิบายเป้าหมายให้ชัด, บอกว่าผลลัพธ์ที่ดีหน้าตาเป็นอย่างไร, และกำหนด **guardrails** — สิ่งที่ห้ามทำ — เพื่อ "ปฐมนิเทศ" ให้ระบบเข้าใจบริบทธุรกิจก่อนปล่อยให้ทำงานเอง [1][2] ไม่ต้องมีพื้นฐานเขียนโค้ด ใช้ plain English/Thai ได้ตรงๆ

**ขั้นตอนที่ 2 — Real-task experimentation (ทดลองกับงานจริง)**

เลือกงานที่ต้องทำซ้ำทุกสัปดาห์มาให้ AI ลองทำจริง เพื่อเห็นผลประหยัดเวลาที่วัดได้ หัวใจสำคัญของการเป็น manager คือ **review + feedback**: อย่ายอมรับผลงานทันที ให้แก้ไขแล้วบอกว่าปรับอะไรไปบ้าง เพื่อให้ระบบ "เรียนรู้" และทำงานรอบถัดไปได้ดีขึ้น [1] ความเชี่ยวชาญในสายงาน (domain expertise) ของคนเป็นตัวช่วยจับผิดและควบคุมทิศทางงานให้ตรงเป้าที่สุด [3]

**ขั้นตอนที่ 3 — Tool connection ผ่าน MCP (เชื่อมต่อเครื่องมือ)**

เมื่อคุ้นมือแล้ว ขยายผลด้วยการผูกงานหลายอย่างเข้าด้วยกัน แล้วเชื่อมต่อ Claude Code เข้ากับเครื่องมือที่ใช้ประจำผ่าน **MCP (Model Context Protocol)** [1] MCP เป็นมาตรฐานกลาง — เปรียบเหมือน "USB-C สำหรับ AI" — ให้ Claude Code เชื่อมต่อและสั่งการเครื่องมือภายนอกได้อิสระ [4] เช่น เชื่อมกับฐานข้อมูล PostgreSQL, GitHub, หรือ Gmail เพื่อดึงข้อมูล วิเคราะห์ สร้างรายงาน และร่างอีเมลส่งทีมแบบ end-to-end โดยไม่ต้อง copy/paste ข้ามแอปเอง [5]

## User Guide (Step-by-Step)

1. **Install** — ติดตั้ง Claude Code ตามคู่มือทางการ (`code.claude.com/docs`) ไม่ต้องมีพื้นฐานเขียนโค้ดมาก่อน [5]
2. **ปฐมนิเทศด้วยภาษาธรรมชาติ** — เปิดงานแรกด้วยการอธิบายเป้าหมายเป็นประโยคปกติ เช่น "ช่วยสรุปยอดขายจากไฟล์ Excel นี้เป็น bullet 5 ข้อ ห้ามเปลี่ยนตัวเลขในไฟล์ต้นฉบับ" — ผลลัพธ์ที่ควรได้: สรุปตรงประเด็น พร้อม guardrail ที่ระบุไว้ถูกเคารพ
3. **ทดลองกับงานจริงที่ทำซ้ำทุกสัปดาห์** — เลือกงาน routine เช่น จัดฟอร์แมตรายงาน หรือดึงข้อมูลจากหลายไฟล์มารวมกัน ให้ AI ลองทำ แล้ว **review ผลลัพธ์ทุกครั้ง** — แก้ไขและบอกเหตุผลที่แก้ เพื่อให้รอบถัดไปแม่นขึ้น
4. **เชื่อมต่อเครื่องมือผ่าน MCP** — เมื่อมั่นใจแล้ว เพิ่ม MCP server ที่เกี่ยวกับงานประจำ (เช่น Google Drive, GitHub, ฐานข้อมูล) ผ่านคำสั่งตามเอกสารทางการ [5] แล้วให้ AI ทำงานข้ามระบบให้ครบวงจรในคำสั่งเดียว เช่น "ดึงยอดขายจาก DB เดือนนี้ สรุปเป็นรายงาน แล้วร่างอีเมลส่งทีม"
5. **Troubleshooting** — ถ้า AI ทำเกินขอบเขตที่ตั้งใจ ให้ปรับ guardrail ในขั้นตอนที่ 2 ให้ชัดเจนขึ้น (ระบุสิ่งที่ห้ามทำแบบเจาะจง) แทนที่จะปล่อยให้ระบบเดาเจตนา

## Caveats / Limits

- Agentic AI ยังต้องมีคน **review ผลลัพธ์** เสมอ — ไม่ใช่ระบบที่ปล่อยทำงานได้โดยไม่มีคนตรวจสอบ โดยเฉพาะงานที่กระทบข้อมูลจริงหรือส่งออกภายนอก [1]
- ความแม่นยำของ agent ขึ้นกับความชัดเจนของ guardrail ที่ผู้ใช้กำหนด — คำสั่งกำกวมนำไปสู่ผลลัพธ์ที่ผิดทิศทางได้ง่าย [1][2]
- การเชื่อมต่อ MCP กับเครื่องมือภายนอก (ฐานข้อมูล, อีเมล) มีความเสี่ยงด้าน security/permission — ควรจำกัดสิทธิ์การเข้าถึงเท่าที่จำเป็นเท่านั้น [4]
- domain expertise ของผู้ใช้ยังจำเป็น เพื่อจับความผิดพลาดที่ agent มองไม่เห็นเอง [3]

- ทักษะสำคัญตอนนี้คือการเป็น **AI Manager** ไม่ใช่การเขียนโค้ดเก่งขึ้น
- 3 ขั้นตอน: สื่อสารด้วยภาษาธรรมชาติ (พร้อม guardrail) → ทดลองกับงานจริงที่ทำซ้ำ + review/feedback → เชื่อมต่อเครื่องมือผ่าน MCP
